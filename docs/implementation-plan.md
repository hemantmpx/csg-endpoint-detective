# Implementation plan

1. **Repository/bootstrap:** independent classroom repository, documentation, Next.js shell, FastAPI service, PostgreSQL, Compose, and health checks.
2. **Scenario model:** preserve the first two cases; define canonical incident timelines, CSG transitions, Snapshot Delta data, separate Wazuh coverage, five variants, and private answer keys.
3. **Sessions:** class-code join, opaque cookie session, stable variant assignment, progress persistence.
4. **CSG workspace:** snapshot inventory, Snapshot Delta cards, separate CSG State Change Timeline, evidence tray.
5. **Wazuh workspace:** allow-listed query parser, indexed search, filters, histogram, pagination, normalized detail and raw JSON.
6. **Reconciliation:** five classifications including `PARTIALLY_EXPLAINED`, item-level evidence selection, partial scoring, and post-submit answer reveal.
7. **Instructor and hardening:** protected dashboard, class controls, CSV export, privacy/answer-key checks, classroom documentation, Docker operation.
8. **Verification:** run scenario validation and requested unit/API/UI checks, exercise independent sessions, and run the 50-user load simulation where the local runtime supports it. Record actual results and environment limits in `BUILD_STATUS.md`.

The CSG research tree remains read-only throughout. CSG transitions are independent scenario data; they are not derived from Wazuh event rows.
